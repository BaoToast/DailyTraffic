# 全日交通量及車種組成－GitHub Pages 備用版

目前版本：**v20.10（2026-08-22）**

網站工具列提供「新手使用手冊 PDF」與可編輯 Word 版下載（v20.10 已全面改寫）。內容以「完全沒有交通背景」的使用者為對象：先用白話解釋交通量調查、輛數與 PCU 的差別、當量係數、尖峰小時等名詞，再帶著操作匯入、檢查、時段分析、報表輸出與備份，最後附常見問題與每季作業檢查表，共 18 章。

本版同時支援原有雙向路段格式，以及 3～7 支線的路口轉向全日交通量格式。車種數量不再固定為四種：系統會保留檔案內實際偵測到的所有車種，使用者可讓新增車種獨立分析並設定一般及轉向PCU係數，也可歸類至機車、小型車、大型車或特種車後重新彙整。原始車種數量不會因歸類而被改寫，車種設定會同步套用至全日量、PCU、尖峰、組成比例、歷季趨勢、明細及 Excel 匯出。

PCU 當量係數完全由使用者自訂，不設最小值或固定增量；一般、直行、右轉與左轉係數皆直接依輸入值重新計算。

### v20.10 修正：時段車種分析「不管怎麼切換篩選條件，前幾列都不會變」

- **症狀**：在「時段車種分析」把「分析時段」切成「僅顯示上午尖峰小時」、或改選某個方向，表格前面好幾列仍舊維持原樣（顯示全日、全日尖峰、下午尖峰，以及沒被選到的方向），只有最後才多出一列正確的結果。
- **原因**：v20.9 新增的「駛出＋駛入並列」對**路段格式**會把每一列輸出兩次——路段只有方向A／方向B，沒有駛入／駛出之分，兩種視角算出來一模一樣。重複的列讓 React 的 key 撞號，接著再更動任何篩選條件時，舊的列就不會被移除，看起來便像是「篩選完全沒有作用」。
- **修正**：並列模式只對**路口格式**展開兩種視角，路段格式維持一列；同時在列的 key 加上列序，日後即使再出現內容相同的兩列，也不會把舊的列留在畫面上。
- 已新增自動測試：驗證並列模式不會產生重複列、以及切換分析時段後每一列都確實是所選的時段。

### v20.9：每個分析區塊都能就地切換條件；PCU 係數完全獨立

**一、每個分析區塊都有自己的篩選列**

- 條件全部集中在頁面最上方，換一次條件就要把畫面捲上去再捲回來——區塊越下面越麻煩。現在**路段排名、每小時趨勢、平假日比較、跨計畫比較、路段明細表、路口明細表、時段車種分析**都有自己的篩選列，只列出該區塊真正吃得到的條件（季度／日別／調查點／路口流量視角／車流方向）。
- 這些控制項與最上方的工具列**綁的是同一組狀態**，在哪一邊改都會同步，不會出現兩套互相矛盾的條件。車種組成與歷季趨勢本來就有自己的控制項，維持原樣。
- 篩選列的字級、控制項高度與內距一律沿用全站既有的樣式（9px 標籤 ＋ 31px 下拉 ＋ 左右 18px 內距），與原本的篩選器、車種組成控制項一致；寬面板排成一列、右欄的窄面板自動折成兩列，不會把面板撐高或插進一塊風格突兀的區域。

**三、修正「路段排名」面板下方一大片空白**

- 該面板在圖表網格中跨兩列，好讓右欄能疊放「車種組成」與「每小時趨勢」兩個面板。但當調查點只有兩三個時，它會被拉成與右欄同高，下半部就是一整片空白的白框（區塊篩選列讓右欄變高後更明顯）。現已改為靠上對齊：面板只佔自己需要的高度，多出來的是網格空隙而不是空白面板。

**二、PCU 當量係數完全獨立，並在畫面上標示屬於哪個計畫**

- v20.8 雖然改成每計畫各存一組，但「還沒自己設定過的計畫」仍會沿用升級前那一組共用值——使用者依然分不出畫面上的數字是不是自己設的。
- 現在升級時會把舊的那一組**明確寫進當時已存在的每一個計畫**，之後就沒有任何共用來源：**新建立的計畫一律從系統預設值開始**。
- 係數區塊上方直接標示「PCU 當量係數・計畫：○○」與「這一組係數只屬於本計畫，不會影響其他計畫」；若該計畫從未自行設定過，會再註明「本計畫尚未自行設定，目前使用系統預設值」，一眼就能確認自己改的是哪一個計畫。

### v20.8：四項修正

**一、各計畫的 PCU 當量係數沒有分開存**

- 在 B 計畫把機車改成 0.42 之後，切回 A 計畫也會變成 0.42。舊版的一般係數與轉向係數都只存一組（`traffic-pcu-factors-v1`），所有計畫共用，等於把某個計畫的標準套到別的計畫的數據上，而且畫面不會有任何提示。
- 現已改成**每個計畫各存一組**（`traffic-pcu-factors-by-project-v1`、`traffic-turn-pcu-factors-by-project-v1`），切換計畫時自動載入該計畫自己的係數；「套用係數」「恢復預設」「套用範本」「還原備份」都只影響目前這個計畫。升級前存的那一組會保留為「還沒自己設定過的計畫」的預設值，既有資料不會跑掉。

**二、匯出的前兩張圖在「整季只有路口資料」時是空白的**

- 「各路段全日實際交通量」與「各路段24小時PCU」原本固定參照「本季交通量及PCU」工作表，而該表只收**路段格式**。整季全是路口時，那張表只有一列「本季無路段格式資料」的提示，於是圖有標題、有座標軸、有圖例，卻一根柱子都沒有。現已改成：整季沒有路段格式時，這兩張圖自動改參照「路口駛出／駛入交通量」工作表的各支線，標題同步改為「各支線…」；兩種格式都有時維持原本行為。

**三、時段車種分析可以自己切換視角，不必捲回最上方**

- 這一區在頁面最下方，但條件（季度、日別、調查點、路口流量視角）全都在最上方的工具列，每換一個條件就要捲上去再捲回來。現在這一區自己就有**季度／日別／路段·路口**篩選器（與上方共用同一組設定，在哪邊改都同步），以及自己的**路口流量視角**（駛出／駛入／兩者並列），不必再來回捲動。
- 「兩者並列」會同時列出同一支線的駛出與駛入兩列，合計那一列會標明是哪一邊；兩種視角的合計數值必定相同。

**四、Excel 匯出選項補上這兩個條件**

- 匯出中心原本只能勾時段、方向與數值，無法指定「尖峰時段認定」與「路口流量視角」——想匯出特定組合，只能先在畫面上調好再匯出，而且存成範本也記不住。現已把這兩項加入匯出中心，預設「跟隨畫面上的設定」，也可明確指定；兩者都會跟著「自訂比較報表」範本一起存檔與還原。

- **匯出的「各路段全日實際交通量」與「各路段24小時PCU」兩張圖是空的。** 這兩張圖原本固定參照「本季交通量及PCU」工作表，而該表只收**路段格式**的資料。整季調查全是路口時，那張表只有一列「本季無路段格式資料」的提示，於是圖有標題、有座標軸、有圖例，卻一根柱子都沒有。現已改成：整季沒有路段格式時，這兩張圖自動改參照「路口駛出／駛入交通量」工作表的各支線（欄位 F／G／H），標題同步改為「各支線…」；兩種格式都有時維持原本行為。以實測檔驗證，改版後兩張圖各有 4 個資料點並正常繪出長條。
- 補充：**9 張圖全部放在同一張「可編輯圖表」工作表上**，不是散落在各資料表旁邊。若在其他頁籤找不到圖，請切到該頁籤。
- **時段車種分析新增自己的「路口流量視角」下拉。** 這一區原本只能跟著上方工具列的視角，想看另一種就得去改上方設定、連帶影響其他所有表單。現在可在這一區單獨選「駛出路口」「駛入路口」，或選「駛出＋駛入並列」一次看到兩種視角；並列時合計那一列會標明是哪一邊，兩者的合計數值必定相同。

### v20.5 修正：「駛入／駛出」用詞對調，名稱終於與數值一致

- **舊版的名稱與實際計算剛好相反。** 畫面上寫「駛入路口X」，算的卻是以 X 為**起點**的車（從 X 開出去、進入路口）；「駛出路口X」算的卻是以 X 為**終點**的車。這與一般講法不符——「駛入路口X」應該是指車輛從其他支線**駛入 X**。
- **本版把兩個名稱對調，數值本身完全沒有變動。** 現在：「駛出路口X」＝以 X 為**起點**（原始調查表直接記錄的角度，系統預設視角）；「駛入路口X」＝以 X 為**終點**（依路口幾何的轉向去向推算）。兩種視角都保留，用篩選器的「路口流量視角」切換，可分別查得同一個路口的駛出量與駛入量。
- 兩種視角的**總計必定相同**，只有各支線的分佈不同。以使用者提供的七叉路口實測檔驗證：切到「駛入」時，上午尖峰各支線為 422.4／414.3／628.5／56.2／184.5／1703.2／567.5，與原檔「進入該路口交通量」完全相同。
- **同時全面清掉殘留的反向用詞**：品質與定稿面板、明細表欄位、匯出設定表與提示訊息裡的「未指定駛出路口／未指定駛出量」全部改為「未指定駛入」（那個欄位裝的是「找不到終點」的車流）；路口幾何面板中央的「由 A 駛入」改為「由 A 駛出」；面板下方那句解釋原本把兩者說反了，也一併更正。
- **若您手上有 v20.4 以前輸出的報表**，其中的「駛入路口X」對應本版的「駛出路口X」，反之亦然；數字不需要重算，只需更正欄位名稱。
- 「路口轉向」系統（Turning Traffic）同步發布 v2.1.3，採用完全相同的定義，兩支程式的用詞不會再有落差。

### v20.2 新增：上下午各 N 小時的部分時段調查

- **新增部分時段（非 24 小時）調查格式的完整分析**。實務上常見只調查上午與下午各數小時、且以 15 分鐘為一格的路口轉向調查表，本版起可直接匯入，並與既有的全日格式共用同一套分析：尖峰明細、車種組成、時段車種分析、歷季趨勢、平假日比較、報表匯出與圖表全部適用。
- **尖峰小時改用滾動視窗**（僅適用於這類細格資料）。連續 4 格（＝1 小時）為一個視窗，每 15 分鐘推移一次，上午與下午各自取最大值，且視窗不會跨越上下午之間的空檔。原本每小時一列的全日格式完全走原路徑，計算結果不變。依 2022 年臺灣公路容量手冊，手冊只定義尖峰小時係數（式 2.10）與設計小時流量係數，並未規定固定的尖峰時鐘區間，因此尖峰必須由實測資料搜尋。
- **全日交通量為實際調查時段的加總**，並在表格上方以文字標明「本筆非 24 小時調查：實際只調查 07:00～09:00、17:00～19:00，合計 4 小時」，欄位標題同步改為「全日（輛/調查日）」「調查時段合計（PCU）」，避免與完整 24 小時調查的數值混用。
- **支援任意叉數的路口**。除了原本「一張工作表、各支線並排」的版型（三叉、十字路口等），新增支援「一條支線一張工作表」且欄位為「往B、往C、往D…」的版型（七叉路口常見）。系統會自動從工作表的「路口編號：X」判讀支線代碼、從「日期：…(平日)」判讀日別，並自動略過監測日誌、時相圖、照片等工作表。
- **目的支線自動歸類為左轉／直行／右轉**。「往B、往C…」格式沒有轉向欄位，系統依「路口幾何」中各支線的角度自動判定每一個目的地屬於左轉、直行或右轉，再套用對應的轉向 PCU 係數。分類結果不會寫死在資料裡：日後在「路口幾何」調整角度或駛出對應，所有分析會立即依新幾何重新計算，不需要重新匯入。原始各目的地的車輛數會完整保存，供追溯與核對。
- 以使用者提供的實際調查檔驗證：三叉路口上午尖峰 07:00～08:00＝3,373 PCU/hr、下午 17:00～18:00＝2,994.9；十字路口 07:15～08:15＝2,953.8、17:00～18:00＝2,575.5；七叉路口的四車種輛數（808／360／16／5）與原檔完全一致。

### v20.1 修正（全面檢查）

- **匯入確認視窗會蓋住原視窗**：選好檔案後跳出「確認匯入」時，原本的匯入視窗沒有關閉，兩個視窗疊在一起，容易誤以為匯入沒有成功。現已改成跳出確認視窗前先收起匯入視窗；按「取消」則回到匯入視窗，流程不會中斷。
- **舊版 .xls 匯出未遵守勾選**：舊版格式過去一律輸出全部工作表，與新版 .xlsx 的「匯出項目」勾選不一致。現已改成兩種格式都依勾選裁切，且全部取消勾選時會提示而不是輸出空檔。
- **面板上的「下載此圖 Excel」略過勾選檢查**：現已把守門條件移入匯出程序本身，任何入口都不會再產生沒有工作表的壞檔。
- **匯入失敗仍留下新車種設定**：新車種的預設當量改為等檔案真的上傳並匯入成功後才寫入，失敗時不會留下沒有資料的車種。
- **PCU 係數可被設為 0**：係數是乘數，0 會讓該車種在所有分析中消失。現已限制獨立車種的四個係數都必須大於 0。
- **切回獨立車種時當量被覆蓋**：把某車種併入四大類後再切回獨立分析，原本自訂的四個當量會被四大類的值蓋掉；現已改為自動還原成使用者先前設定的值。
- **換計畫或換季度後時段分析空白**：原本勾選的調查點代碼若在新資料中不存在，畫面與匯出都會變成一列都沒有。現已在資料變動時自動清除已不存在的勾選。
- **其他**：備份還原時一併驗證並保存 PCU 係數、比較報表範本套用前先驗證欄位、修正尖峰小時在整日流量為 0 或時間欄位無法解析時的判定、修正跨日別分組時同名調查點被併在一起、避免「全部支線（ALL）」被重複計入。

### v20.0 新增

- **時段車種分析（獨立區塊）**：在儀表板最下方獨立一區，同時提供「全日時段（24 小時加總）」「全日尖峰小時」「上午尖峰小時」「下午尖峰小時」四種時段下，各調查點、各方向的每一種車種車輛數、百分比與交通流量（PCU/hr）。可切換只看某一個時段、切換顯示車輛數／百分比／交通流量，也可只顯示指定的方向或支線。這一區與上方所有既有表單完全獨立，不會互相影響。
- **尖峰小時認定方式**：2022 年臺灣公路容量手冊只定義尖峰小時係數（式 2.10，PHF＝尖峰小時流率÷尖峰 15 分鐘流率）與設計小時流量係數 K，並未規定固定的尖峰時鐘區間，因此尖峰小時一律由實測資料認定——上午尖峰取中午 12:00 之前當量交通量最高的 1 小時、下午尖峰取 12:00 之後最高的 1 小時、全日尖峰取 24 小時中最高的 1 小時。判定基準為 PCU（手冊 2.4.13：容量分析以小客車單位量為共同尺規），且每個「調查點×方向」各自認定自己的尖峰小時。
- **方向搭配**：路口格式會依「駛出路口 A～G」或「駛入路口 A～G」（跟著上方的路口流量視角切換）分列；路段格式依方向 A／方向 B 分列，另外都會多一列雙向／全部支線合計。
- **報表匯出項目由使用者決定**：匯出中心可勾選要匯出哪些時段、哪些方向／支線、哪一種數值（車輛數／百分比／交通流量），勾選的每個時段各產生一張工作表，也可改成全部併成一張大表。勾選內容可與季度、日別、調查點等條件一起存成「自訂比較報表」範本，不同計畫各存一組，之後按「套用」即整組還原。
- **修正**：匯出中心的七個區塊勾選原本被「9 張可編輯原生圖表」的條件包住，只要圖表是勾的（預設就是勾的），其他勾選完全不會生效。現已改成永遠依勾選裁切；若某張圖表所需的資料表被取消勾選，該圖表也會一併略過，避免 Excel 開檔時出現修復提示。
- **新車種當量預設值**：匯入偵測到預設四大類以外的車種時，不再逐一跳出視窗要求輸入當量係數；一律先保留為獨立車種並把一般／直行／右轉／左轉 PCU 預設為 1，再由使用者到「車種分類與新增當量」手動調整。
- **修正原四大類當量顯示不同步**：在外面的「PCU 當量係數」把機車改成 0.42 並套用後，「車種分類與新增當量」內鎖定的機車欄位過去仍顯示舊的 0.5（實際計算用的是 0.42）。現已改成鎖定欄位直接顯示外部係數目前的值，並在套用係數時把儲存的值一併同步，兩邊永遠是同一個數字。

最終版新增匯入前品質檢核、來源儲存格追溯、歷季異常警示、匯入版本復原、專案設定範本、資料完整性儀表板、批次報表輸出、草稿／待確認／已確認／定稿流程，以及可儲存並重複套用的自訂比較報表範本。定稿季度會阻擋未確認的覆蓋，完整備份會一併保存品質與版本設定。

## 發布方式

1. 在 GitHub 建立一個新的 repository。
2. 將發行壓縮檔解壓縮後，把 `index.html`、`assets` 資料夾及本說明檔上傳到 repository 根目錄。
3. 進入 repository 的 **Settings → Pages**。
4. 在 **Build and deployment** 選擇 **Deploy from a branch**。
5. Branch 選擇 `main`，資料夾選擇 `/ (root)`，再按 **Save**。

## 資料保存方式

- 資料保存於目前瀏覽器的 IndexedDB，關閉或重新整理網頁不會消失。
- A、B 電腦不會自動同步；請在 A 電腦按「匯出備份」，再到 B 電腦使用「匯入季度資料 → 從其他電腦還原完整備份」。
- 清除瀏覽器網站資料前，請先匯出備份。
- GitHub Pages 備用版不支援多人即時分享、帳號權限及雲端同步；這些功能請使用 GPT Site 正式版。

## 未來更新

每次 GPT Site 更新後，重新產生本發行包並以新版的 `index.html` 與 `assets` 完整覆蓋 GitHub repository 內的舊檔案。使用者的交通資料存在瀏覽器中，不會因網站程式更新而被覆蓋，但更新前仍建議先匯出備份。
