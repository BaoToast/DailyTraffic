# 全日交通量及車種組成－GitHub Pages 備用版

目前版本：**v20.4（2026-08-22）**

網站工具列提供「新手使用手冊 PDF」與可編輯 Word 版下載（v20.4 已全面改寫）。內容以「完全沒有交通背景」的使用者為對象：先用白話解釋交通量調查、輛數與 PCU 的差別、當量係數、尖峰小時等名詞，再帶著操作匯入、檢查、時段分析、報表輸出與備份，最後附常見問題與每季作業檢查表，共 18 章。

本版同時支援原有雙向路段格式，以及 3～7 支線的路口轉向全日交通量格式。車種數量不再固定為四種：系統會保留檔案內實際偵測到的所有車種，使用者可讓新增車種獨立分析並設定一般及轉向PCU係數，也可歸類至機車、小型車、大型車或特種車後重新彙整。原始車種數量不會因歸類而被改寫，車種設定會同步套用至全日量、PCU、尖峰、組成比例、歷季趨勢、明細及 Excel 匯出。

PCU 當量係數完全由使用者自訂，不設最小值或固定增量；一般、直行、右轉與左轉係數皆直接依輸入值重新計算。

### v20.4 修正：多岔路口的「駛出」各支線流量分配錯誤，以及提醒方塊溢出

- **五叉以上路口的「駛出路口X」流量嚴重失真**。舊版把每一條支線的左轉全部歸給單一個目的支線（`leftTarget`），直行、右轉亦然。三叉與十字路口成立，但七叉路口的 A 左轉可能同時通往 B、C、D，全部被塞進同一條之後，各支線的駛出量就完全不對（總計仍正確，所以不容易發現）。現在，若原始檔逐欄記錄了「往B、往C、往D…」，就依實際目的地分配。以使用者提供的七叉路口實測檔驗證，駛出各支線的上午尖峰為 422.4／414.3／628.5／56.2／184.5／1703.2／567.5，與原檔「進入該路口交通量」完全相同；下午同樣完全相同。
- 相關程式已抽成獨立模組 `app/intersection-flow.ts` 並補上 4 項測試（含「沒有目的地欄位的舊格式行為不變」）。這是純搬移，沒有改變既有格式的任何計算。
- **修正部分時段提醒方塊的版面**。該方塊原本套用了本專案並不存在的 `.warning` 樣式，等於沒有任何框線與內距，文字會貼齊面板邊緣並溢出框外。現已補上正式樣式並加上左右留邊，並在測試中檢查它不會超出所在面板。
- 補充說明：畫面上的「駛入路口X」是依**起點**統計（從 X 開進路口的車），「駛出路口X」是依**終點**統計（最後開進 X 的車）。兩者總計必定相同，但各支線的分佈不同，比對報表時請確認用的是同一種視角。

### v20.3 修正：尖峰小時卡片仍顯示 15 分鐘流率

- **儀表板頂端「尖峰小時當量交通量」卡片與各方向尖峰，在部分時段（15 分鐘一格）資料下顯示的是「最大的單一 15 分鐘格」，而不是尖峰小時。** v20.2 已把明細表與時段分析改成滾動一小時，但這張卡片走的是另一段程式，漏改了。以七叉路口實測檔為例，卡片會顯示「07:30～07:45　1,263.8 PCU/小時」，那其實是最大的 15 分鐘流率；正確的尖峰小時是 07:15～08:15、3,976.6 PCU/hr。
- 現已把全系統的尖峰計算統一到單一函式 `peakFromBuckets`：每小時一列的資料取最大的那一列（結果與以往完全相同），15 分鐘等細格資料則取連續湊滿一小時的滾動視窗最大值，平日與假日各自計算、不跨日別。並補上三項回歸測試，避免同樣的漏改再次發生。
- 以使用者提供的三叉路口實測檔驗證：卡片顯示 07:00～08:00＝3,373 PCU/hr，與原檔一致。

### v20.2 新增：上下午各 N 小時的部分時段調查

- **新增部分時段（非 24 小時）調查格式的完整分析**。實務上常見只調查上午與下午各數小時、且以 15 分鐘為一格的路口轉向調查表，本版起可直接匯入，並與既有的全日格式共用同一套分析：尖峰明細、車種組成、時段車種分析、歷季趨勢、平假日比較、報表匯出與圖表全部適用。
- **尖峰小時改用滾動視窗**（僅適用於這類細格資料）。連續 4 格（＝1 小時）為一個視窗，每 15 分鐘推移一次，上午與下午各自取最大值，且視窗不會跨越上下午之間的空檔。原本每小時一列的全日格式完全走原路徑，計算結果不變。依 2022 年臺灣公路容量手冊，手冊只定義尖峰小時係數（式 2.10）與設計小時流量係數，並未規定固定的尖峰時鐘區間，因此尖峰必須由實測資料搜尋。
- **全日交通量為實際調查時段的加總**，並在表格上方以文字標明「本筆非 24 小時調查：實際只調查 07:00～09:00、17:00～19:00，合計 4 小時」，欄位標題同步改為「全日（輛/調查日）」「調查時段合計（PCU）」，避免與完整 24 小時調查的數值混用。
- **支援任意叉數的路口**。除了原本「一張工作表、各支線並排」的版型（三叉、十字路口等），新增支援「一條支線一張工作表」且欄位為「往B、往C、往D…」的版型（七叉路口常見）。系統會自動從工作表的「路口編號：X」判讀支線代碼、從「日期：…(平日)」判讀日別，並自動略過監測日誌、時相圖、照片等工作表。
- **目的支線自動歸類為左轉／直行／右轉**。「往B、往C…」格式沒有轉向欄位，系統依「路口幾何」中各支線的角度自動判定每一個目的地屬於左轉、直行或右轉，再套用對應的轉向 PCU 係數。分類結果不會寫死在資料裡：日後在「路口幾何」調整角度或駛出對應，所有分析會立即依新幾何重新計算，不需要重新匯入。原始各目的地的車輛數會完整保存，供追溯與核對。
- 以使用者提供的實際調查檔驗證：三叉路口上午尖峰 07:00～08:00＝3,373 PCU/hr、下午 17:00～18:00＝2,994.9；十字路口 07:15～08:15＝2,953.8、17:00～18:00＝2,575.5；七叉路口的四車種輛數（808／360／16／5）與原檔完全一致。

### v20.1 修正（全面檢查）

- **匯入確認視窗會蓋住原視窗**：選好檔案後跳出「確認匯入」時，原本的匯入視窗沒有關閉，兩個視窗疊在一起，容易誤以為匯入沒有成功。現已改成跳出確認視窗前先收起匯入視窗；按「取消」則回到匯入視窗，流程不會中斷。
- **舊版 .xls 匯出未遵守勾選**：舊版格式過去一律輸出全部工作表，與新版 .xlsx 的「匯出項目」勾選不一致。現已改成兩種格式都依勾選裁切，且全部取消勾選時會提示而不是輸出空檔。
- **面板上的「下載此圖 Excel」略過勾選檢查**：現已把守門條件移入匯出程序本身，任何入口都不會再產生沒有工作表的壞檔。
- **匯入失敗仍留下新車種設定**：新車種的預設當量改為等檔案真的上傳並匯入成功後才寫入，失敗時不會留下沒有資料的車種。
- **PCU 係數可被設為 0**：係數是乘數，0 會讓該車種在所有分析中消失。現已限制獨立車種的四個係數都必須大於 0。
- **切回獨立車種時當量被覆蓋**：把某車種併入四大類後再切回獨立分析，原本自訂的四個當量會被四大類的值蓋掉；現已改為自動還原成使用者先前設定的值。
- **換計畫或換季度後時段分析空白**：原本勾選的調查點代碼若在新資料中不存在，畫面與匯出都會變成一列都沒有。現已在資料變動時自動清除已不存在的勾選。
- **其他**：備份還原時一併驗證並保存 PCU 係數、比較報表範本套用前先驗證欄位、修正尖峰小時在整日流量為 0 或時間欄位無法解析時的判定、修正跨日別分組時同名調查點被併在一起、避免「全部支線（ALL）」被重複計入。

### v20.0 新增

- **時段車種分析（獨立區塊）**：在儀表板最下方獨立一區，同時提供「全日時段（24 小時加總）」「全日尖峰小時」「上午尖峰小時」「下午尖峰小時」四種時段下，各調查點、各方向的每一種車種車輛數、百分比與交通流量（PCU/hr）。可切換只看某一個時段、切換顯示車輛數／百分比／交通流量，也可只顯示指定的方向或支線。這一區與上方所有既有表單完全獨立，不會互相影響。
- **尖峰小時認定方式**：2022 年臺灣公路容量手冊只定義尖峰小時係數（式 2.10，PHF＝尖峰小時流率÷尖峰 15 分鐘流率）與設計小時流量係數 K，並未規定固定的尖峰時鐘區間，因此尖峰小時一律由實測資料認定——上午尖峰取中午 12:00 之前當量交通量最高的 1 小時、下午尖峰取 12:00 之後最高的 1 小時、全日尖峰取 24 小時中最高的 1 小時。判定基準為 PCU（手冊 2.4.13：容量分析以小客車單位量為共同尺規），且每個「調查點×方向」各自認定自己的尖峰小時。
- **方向搭配**：路口格式會依「駛入路口 A～G」或「駛出路口 A～G」（跟著上方的路口流量視角切換）分列；路段格式依方向 A／方向 B 分列，另外都會多一列雙向／全部支線合計。
- **報表匯出項目由使用者決定**：匯出中心可勾選要匯出哪些時段、哪些方向／支線、哪一種數值（車輛數／百分比／交通流量），勾選的每個時段各產生一張工作表，也可改成全部併成一張大表。勾選內容可與季度、日別、調查點等條件一起存成「自訂比較報表」範本，不同計畫各存一組，之後按「套用」即整組還原。
- **修正**：匯出中心的七個區塊勾選原本被「9 張可編輯原生圖表」的條件包住，只要圖表是勾的（預設就是勾的），其他勾選完全不會生效。現已改成永遠依勾選裁切；若某張圖表所需的資料表被取消勾選，該圖表也會一併略過，避免 Excel 開檔時出現修復提示。
- **新車種當量預設值**：匯入偵測到預設四大類以外的車種時，不再逐一跳出視窗要求輸入當量係數；一律先保留為獨立車種並把一般／直行／右轉／左轉 PCU 預設為 1，再由使用者到「車種分類與新增當量」手動調整。
- **修正原四大類當量顯示不同步**：在外面的「PCU 當量係數」把機車改成 0.42 並套用後，「車種分類與新增當量」內鎖定的機車欄位過去仍顯示舊的 0.5（實際計算用的是 0.42）。現已改成鎖定欄位直接顯示外部係數目前的值，並在套用係數時把儲存的值一併同步，兩邊永遠是同一個數字。

最終版新增匯入前品質檢核、來源儲存格追溯、歷季異常警示、匯入版本復原、專案設定範本、資料完整性儀表板、批次報表輸出、草稿／待確認／已確認／定稿流程，以及可儲存並重複套用的自訂比較報表範本。定稿季度會阻擋未確認的覆蓋，完整備份會一併保存品質與版本設定。

## 發布方式

1. 在 GitHub 建立一個新的 repository。
2. 將發行壓縮檔解壓縮後，把 `index.html`、`assets` 資料夾及本說明檔上傳到 repository 根目錄。
3. 進入 repository 的 **Settings → Pages**。
4. 在 **Build and deployment** 選擇 **Deploy from a branch**。
5. Branch 選擇 `main`，資料夾選擇 `/ (root)`，再按 **Save**。

## 資料保存方式

- 資料保存於目前瀏覽器的 IndexedDB，關閉或重新整理網頁不會消失。
- A、B 電腦不會自動同步；請在 A 電腦按「匯出備份」，再到 B 電腦使用「匯入季度資料 → 從其他電腦還原完整備份」。
- 清除瀏覽器網站資料前，請先匯出備份。
- GitHub Pages 備用版不支援多人即時分享、帳號權限及雲端同步；這些功能請使用 GPT Site 正式版。

## 未來更新

每次 GPT Site 更新後，重新產生本發行包並以新版的 `index.html` 與 `assets` 完整覆蓋 GitHub repository 內的舊檔案。使用者的交通資料存在瀏覽器中，不會因網站程式更新而被覆蓋，但更新前仍建議先匯出備份。
