全日交通量及車種組成 — 完整專案 v20.31
=================================================

■ v20.31-0：異常提醒改寫使用者取的名稱（複查後補的一項）

  「品質與定稿」的異常提醒原本用系統內部的鍵值組字：
    13545-01／平日／駛出路口A custom:大貨車占比變動 10.0 個百分點
  但同一頁上方的表格、車種組成分析、結論草稿、Excel 的其他工作表，
  全部都顯示使用者改過的名稱。同一件事在同一頁上有兩種寫法。

  而這一行字會出現在三個地方：畫面的異常提醒表、Excel 的「品質檢核」
  工作表、以及**報告文字草稿**——最後那個會被直接抄進交付文件。

  本版 detectAnomalies() 新增一個選填的 labels 參數（調查點、支線、車種
  三個解析函式），由畫面層傳入；沒有傳就退回原本的鍵值，行為完全相同。
  AnomalyAlert 另外多出 roadLabel／directionLabel／vehicleLabel 三個顯示欄位，
  原本的 roadId／direction／vehicle 鍵值一個字都沒有改——分組與篩選靠的是它們。

  ⚠️ 判定門檻與數值完全沒有變動，只是把名字寫對。

  新增單元測試 4 項，其中 3 項已實測會在未修正的舊寫法下紅字。

■ v20.31-1：把使用者的真實調查檔從程式包裡拿掉（重要）

  複查發現：tests/fixtures/ 底下放著一份實際的七叉路口調查表
  （.xlsx 與 .xls 各一份），被兩支自動測試當成參考檔使用。
  它因此進了公開的 GitHub repository，而且可以直接從 GitHub Pages 下載。

  測試需要的是「這種檔案長什麼樣」，不是「這一份實際調查到多少車」。
  本版新增 tests/helpers/intersection-sample.mjs：測試執行時當場產生一份
  結構與真實檔完全相同（一支線一張工作表、車種×目的支線、16 個 15 分鐘時段、
  連合併儲存格造成的重複車種標題都照抄）、數字用固定種子自己編的活頁簿。

  期望值反而更嚴格了：以前是拿使用者參考檔的彙總數字來比，
  現在是拿樣本的每一格真值自己加總出來比，而且那個加總完全不經過被測試的程式。

  已移除：tests/fixtures/（兩個實際檔案）、scripts/e2e-partial.mjs
  （它只讀那兩個實際檔案，不在 npm run e2e 流程裡，交付出去也跑不起來）。
  測試與手冊裡的實際站號、調查點名稱與該次調查的數值也一併換成示範資料。

  ⚠️ 刪掉檔案不等於刪掉歷史。Git 會保留舊的 commit，
     這一版只保證「之後不會再有」，已經公開過的內容要另外處理。

■ v20.31-2：三道新的自動檢查

  1. 交付包裡不得出現任何試算表檔案（.xlsx／.xls／.xlsm／.csv）。
  2. 原始碼裡不得出現實際站號（5 碼計畫編號＋T＋兩碼＋兩碼）。
  3. 必須有 .gitattributes 且關閉換行轉換。

  三項都已實測會在對應的錯誤狀態下失敗：把實際檔放回 tests/fixtures、
  把站號寫回測試、刪掉 .gitattributes——各自紅字，還原後全部通過。

■ v20.31-3：換行字元不再被自動改寫

  上一版的備份 ZIP 裡每一個文字檔都被轉成 CRLF，連 vite 的建置產物也一樣，
  結果 assets/index-<雜湊>.js 的內容不再雜湊成它自己的檔名，
  備份包與線上內容無法逐位元核對——而網站照樣跑得動，完全看不出來。
  成因是在 Windows 上取出（core.autocrlf）。
  本版新增 .gitattributes（`* -text`），並把包內所有文字檔正規化為 LF。

  ★ 打包時請用 git archive 從 commit 直接產生，不要用會改寫換行的工具。

■ v20.31-4：`npm run lint` 修好了，而且以後 `npm test` 會跑它

  複查發現 lint 一直是紅的——v20.30 上實測 5687 個錯誤。
  原因是 eslint 沒有排除 assets/ 與 github-pages/dist/，
  在檢查 vite 壓縮後的 bundle；真正的原始碼問題被那幾千筆雜訊蓋住。
  而 npm test 當時沒有跑 lint，所以沒有任何人發現。

  本版：
    1. eslint 設定排除建置產物、手冊成品與測試樣本。
    2. 修掉原始碼真正的問題：9 個未使用的變數與 import、
       5 個多餘的正規表示式跳脫、2 個 any、1 個空的 catch、
       圖例文字的全形空白改成字串（那是刻意的排版字元）。
       正規表示式的改動已用 10 組樣本實測，新舊行為完全相同。
    3. 底線開頭的名稱（_projectId 這種刻意不用的佔位）不再被當成錯誤。
    4. 兩條 React Compiler 的建議規則關閉並寫明理由——本專案沒有啟用
       React Compiler，照它改要動十幾個 effect 的結構，那是與問題無關的重構。
       姊妹專案「路口轉向」早就做過同樣的取捨。
    5. package.json 的 test 改成 `npm run lint && npm run build && …`，
       CI 從此會把關。

  結果：0 錯誤（原 5687）。**還有 6 個 warning**，全部是 useMemo 的相依項
  提示，改了會動到記憶化行為，屬於要單獨評估的事，本版刻意不碰。
  warning 不會讓 lint 失敗。

  ⚠️ 有一處用區塊豁免而不是修掉：DashboardClient 在 render 期間寫入
     window.__TRAFFIC_OFFLINE__。規則的顧慮是對的，但改成 effect 會晚一個
     commit 才設好旗標，而那個旗標的用途正是「在任何 appFetch 之前就決定
     要不要打 API」。原因已寫在程式碼註解裡。

■ 沒有變更任何計算規則

  交通量、PCU、尖峰、車種組成、駛入／駛出全部未動。
  應用程式原始碼只改了兩處：app/system-release.ts 的版號與日期、

■ v20.30：交付包可在乾淨電腦完整重跑自動測試

  外部複查發現 v20.29 的結論草稿端對端測試引用了未放入交付包的
  真實七叉路口活頁簿，因此在乾淨目錄會因找不到檔案而中止，並非文件所述
  的 94/94。本版改用 make-samples.mjs 自行產生的匿名路口樣本，日後不需
  使用者再提供真實調查檔。

  同時修正 Node.js 最低版本宣告：測試會直接載入 TypeScript，Node 22.18.0
  才預設啟用所需支援，因此 engines.node 由 >=22.13.0 改為 >=22.18.0。
  tests/dependency-manifest.test.mjs 也新增兩道檢查，防止最低版本與測試需求
  再次不一致，或端對端測試引用無法由 make-samples.mjs 產生的樣本。

  另外修正 Word 新手手冊的版本戳記分頁位置，不再多出一張幾乎空白的頁面。

■ v20.29-1：多路口並排的調查表只讀到路口A（資料錯誤，已修正）

  使用者回報：一份四個路口並排的調查表匯入後只出現路口A，
  而且那一筆的機車數是四個路口相加（實測 57＋4＋90＋4＝155）。

  成因：舊寫法靠「車種標題重複的週期」推測每個路口佔幾欄。那份檔案的
  路口A、B 寫「大型車／特種車」，路口C、D 卻寫成「大貨車／大客車」
  （調查表的筆誤），週期不成立，於是四個路口的欄位被當成一個路口。
  最麻煩的是它不會報錯：匯入顯示成功，數字也在合理範圍。

  改法：新增 armMarkerColumns()，直接依表頭的「路口編號：路口A」標記切，
  有幾個標記就是幾個路口。找不到標記時（路段調查表）原樣走舊的週期推測。
  新增 tests/arm-split.test.mjs（4 項），已實測第 2、3 項在修正前會失敗。
  以使用者原始檔核對：路口A＝57、B＝4、C＝90、D＝4，與檔案相符。

  ⚠️ 已經匯入過的那一筆請刪掉重新匯入——升版只影響之後匯入的檔案。

■ v20.29-2：匯入前提醒「各支線車種名稱不一致」

  切法修好之後，名稱不一致本身仍多半是打錯字，但匯入一切正常反而
  沒有線索。匯入預覽的「需注意」區會列出不一致的支線與名稱，
  由使用者按確認鈕決定。只提醒，不阻擋、不自動改名、不自動歸類——
  自動把「大貨車」併進「大型車」等於替沒有調查的車種憑空填 0。

  新增單元測試 3 項，已實測「不一致要提醒」那一項在加功能前會失敗。

■ v20.29-3：結論草稿的「方向／支線」可直接選駛入路口

  第四區原本只列得出「駛出路口A…」，要寫駛入得先到上方工具列切視角。
  現在兩種視角都直接列在選項裡。順帶修掉一個潛在錯誤：那一區的列是用
  「駛出」分組算出來的、名稱卻跟著工具列的視角走，切到駛入時會出現
  「名稱寫駛入、數字是駛出」。現在名稱與數字必然一致。
  端對端檢查由 90 項增為 94 項。

  沒有變更任何計算規則：交通量、PCU、尖峰、車種組成的口徑全部未動。

■ v20.28：補齊可重建、可驗證的完整發布工程

  補回 github-pages 建置來源，讓完整專案可以重新產生 GitHub Pages 網站。
  建置指令改為 Windows、macOS 與 Linux 都能使用的方式；npm run e2e
  會先產生測試樣本，再建置網站並執行瀏覽器操作測試。

■ v20.27：結論草稿存好的「條件範本」現在會跟著備份走

  使用者在結論草稿產生器存的條件範本，之前只存在該台電腦的瀏覽器裡，
  匯出的備份檔沒有收——換一台電腦匯入之後範本一個都不剩，
  而畫面只會顯示匯入成功，不會提醒少了什麼。
  本版把 conclusionTemplates 納入 exportBackup()，還原時寫回去。

  還原是**合併**不是覆蓋：同名範本以備份檔為準，本機其他名字的範本保留；
  舊版備份檔（沒有這個欄位）匯入時不會把本機既有範本清掉。
  升版前匯出的舊備份檔裡本來就沒有範本，請使用者重新匯出一份。

  新增 tests/backup-completeness.test.mjs（3 項），以清單比對釘住
  「匯出時有收、匯入時有還原、舊備份不得清空」。

■ v20.26：結論草稿的「時段」說明講清楚了

  「時段」至少要留一個，這一點沒有變——這一區每一項數字都是寫在
  某一個時段底下的，全部取消就一行都寫不出來。但常見的需求是
  「我只要全日的數字」，那不是取消全部，**是只勾「全日」**。
  畫面上的說明原本沒告訴您該怎麼做，本版補上。
  只改說明文字，沒有動任何計算或勾選邏輯。

  手冊裡另外用一張表把三套系統「不勾」的意思一次講清楚
  （本系統不允許全不勾；路口轉向＝不敘述尖峰；交通服務水準＝全部都寫）。

■ v20.25：全日車輛總數不正確、駛入與駛出總數不一致

  早期版本匯入時把四大類車輛數四捨五入成整數存起來，而逐時段的轉向明細
  保留了原始小數（0.36＋11＋1＝12.36 對 12）。一天 24 小時、一個路口
  4 條支線，零頭累積起來就是好幾輛的誤差；「駛入」視角又把兩者的差額
  補進「未指定駛入路口」，而且只補多出來的、不扣少掉的，於是駛入的合計
  比駛出多。改為讀取時優先採用轉向明細，只有差距超過 1 輛才沿用欄位。
  **不需要重新匯入。** 以使用者的真實備份驗證：75 組路口資料、
  涵蓋所有季度，駛入與駛出合計全部相等。

■ v20.24：切到「駛入路口」時調查點欄位仍寫著（駛出）

  每一列只在「並列」模式下才記住自己的視角，單一視角時退回去沿用
  上方工具列的視角來標示。已改為每一列都帶著自己的視角。不影響數字。
